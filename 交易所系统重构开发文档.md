## 一、业务逻辑架构

### 1.1 用户分级系统

| frozen_funds | tinyint | 资金冻结(0=正常,1=冻结) |

#### 用户等级系统 (app/UserLevelModel.php)
- **等级判定逻辑**: 基于充值金额自动升级
- **触发点**: 用户充值审核通过后 (charge_req.status = 2)
- **升级公式**: 累计充值金额 → 匹配 user_level.amount 阈值
- **等级日志**: user_level_log 表记录升级历史

#### 邀请返佣机制
- **三级邀请链**: parent_id → grandparent → great-grandparent
- **返佣触发**: 被邀请人完成交易后，按层级比例分发
- **路径存储**: agent_path 字段存储完整代理路径 (CSV格式)

### 1.2 代理返佣算法

#### 代理商模型 (app/Agent.php)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 代理ID |
| user_id | int | 关联用户ID |
| username | varchar | 代理账号 |
| parent_agent_id | int | 上级代理ID |
| agent_path | string | 代理路径链 |
| level | int | 代理等级(0=超管,1-4=分级) |
| pro_loss | decimal | 头寸收益比例(%) |
| pro_ser | decimal | 手续费返佣比例(%) |
| is_admin | tinyint | 是否超级管理员 |
| is_lock | tinyint | 是否锁定 |
| is_addson | tinyint | 是否可添加下级 |

#### 返佣计算逻辑 (Agent::dojie)
```
头寸收益计算:
1. 获取订单实际盈亏 (fact_profits)
2. 逐级计算极差收益: current_level.pro_loss - parent_level.pro_loss
3. 收益 = 盈亏 * (-1) * (极差比例/100)

手续费收益计算:
1. 获取订单手续费 (trade_fee)
2. 逐级计算极差: current_level.pro_ser - parent_level.pro_ser
3. 手续费返佣 = trade_fee * (极差比例/100)

记录日志: agent_money_log 表
```

#### 代理商层级结构
```
超级代理(is_admin=1, level=0)
    ├── 1级代理(level=1)
    │     ├── 2级代理(level=2)
    │     │     ├── 3级代理(level=3)
    │     │     │     └── 4级代理(level=4)
    │     │     └── 3级代理...
    │     └── 2级代理...
    └── 1级代理...
```

### 1.3 资金账本系统

#### 钱包余额类型
| 类型 | 说明 | 对应字段 |
|------|------|----------|
| 法币账户 | 法币交易余额 | legal_balance / lock_legal_balance |
| 币币账户 | 币币交易余额 | change_balance / lock_change_balance |
| 杠杆账户 | 合约交易余额 | lever_balance / lock_lever_balance |
| 期权账户 | 期权交易余额 | micro_balance / lock_micro_balance |

#### 余额变动触发点 (change_wallet_balance)
| 触发场景 | 余额类型 | 变动方向 | 说明 |
|----------|----------|----------|------|
| 充值到账 | 法币 | + | 用户充值审核通过 |
| 提币申请 | 币币 | - | 申请时扣除可用余额 |
| 提币锁定 | 币币 | +锁定 | 申请时增加锁定余额 |
| 提币成功 | 锁定 | -锁定 | 审核通过后扣除锁定余额 |
| 提币失败 | 锁定 | -锁定 | 拒绝提币释放锁定 |
| 提币退回 | 币币 | + | 失败时退回可用余额 |
| 买入委托 | 法币 | -锁定 | 下单时锁定法币 |
| 卖出委托 | 币币 | -锁定 | 下单时锁定币币 |
| 成交结算 | 对应类型 | +/- | 撮合成功后结算 |
| 合约开仓 | 杠杆 | -锁定 | 开仓保证金锁定 |
| 合约平仓 | 杠杆 | +/- | 平仓后盈亏结算 |

#### 账本流水表 (wallet_log)

|------|------|
| account_log_id | 关联账户日志ID |

```php
// RSA私钥签名
$merchantNo = "3018220814001";
$merchantOrderNo = uniqid();
$signStr = "merchantNo={$merchantNo}&merchantOrderNo={$merchantOrderNo}&amount={$amount}&...";
$private_key = "..."; // RSA私钥
$merchant_private_key = openssl_get_privatekey("-----BEGIN RSA PRIVATE KEY-----\n" . chunk_split($private_key, 64, "\n") . "-----END RSA PRIVATE KEY-----");
openssl_sign($signStr, $sign_info, $merchant_private_key, OPENSSL_ALGO_MD5);
$sign = base64_encode($sign_info);
```
**出参**:
```json
{
  "type": "ok",
  "data": {
    "order_no": "ORDER_xxx",
    "pay_url": "https://...",
```

### 3.2 PostgreSQL迁移方案

#### 类型映射对照表
| MySQL类型 | PostgreSQL类型 | 说明 |
|-----------|----------------|------|
| int | INTEGER | 整型 |
| tinyint | SMALLINT | 小整型 |
| varchar(n) | VARCHAR(n) | 变长字符串 |
| text | TEXT | 长文本 |
| decimal(m,d) | NUMERIC(m,d) | 精确小数 |
| int(11) timestamp | TIMESTAMP | 时间戳 |
| int(11) unixtime | INTEGER | Unix时间戳保留 |

#### 迁移策略
1. **数据导出**: 使用 `mysqldump` 导出为SQL文件
2. **结构转换**: 使用脚本自动转换DDL语句
3. **数据导入**: 使用 `pgloader` 或自定义脚本导入
4. **索引重建**: 按PostgreSQL语法重建索引和约束
5. **序列创建**: 为自增主键创建 SEQUENCE

## 五、核心安全性分析

### 5.1 现有安全机制

#### 5.1.1 密码加密方案 (Users::MakePassword)
```php
public static function MakePassword($password, $type = 0) {
    if ($type == 0) {
        $salt = 'ABCDEFG';
        $passwordChars = str_split($password);
        foreach ($passwordChars as $char) {
            $salt .= md5($char);
        }
    } else {
        $salt = 'TPSHOP' . $password;
    }
    return md5($salt);
}
```
**分析**:
- 使用自定义MD5+salt方案，非标准做法
- salt值固定，可预测性强
- 缺乏密钥派生函数(KDF)
- **重构建议**: 改用 bcrypt/Argon2id

#### 5.1.2 支付RSA签名机制
**私钥签名 (PayController)**:
```php
$private_key = "...RSA私钥...";
$merchant_private_key = openssl_get_privatekey(
    "-----BEGIN RSA PRIVATE KEY-----\n" . 
    chunk_split($private_key, 64, "\n") . 
    "-----END RSA PRIVATE KEY-----"
);
openssl_sign($signStr, $sign_info, $merchant_private_key, OPENSSL_ALGO_MD5);
$sign = base64_encode($sign_info);
```

**公钥验签 (PayNotifyController)**:
```php
$public_key = "...RSA公钥...";
$pay_public_key = openssl_get_publickey(
    "-----BEGIN PUBLIC KEY-----\n" . 
    chunk_split($public_key, 64, "\n") . 
    "-----END PUBLIC KEY-----"
);
$flag = openssl_verify($signStr, base64_decode($sign), $pay_public_key, OPENSSL_ALGO_MD5);
// flag=1 验签成功
```

**分析**:
- 使用RSA-MD5签名，MD5已被攻破
- 密钥硬编码在代码中
- **重构建议**: 升级到 RSA-SHA256 + 密钥管理服务(KMS)

#### 5.1.3 提币安全流程
**用户提币 (WalletController::postWalletOut)**:
```php
public function postWalletOut() {
    // 1. 获取输入参数
    $user_id = Users::getUserId();
    $currency_id = Input::get("currency", 3);
    $number = Input::get("number", '');
    $address = Input::get("address", '');
    
    // 2. 验证支付密码
    $user = Users::getById($user_id);
    $payPassword = Users::MakePassword(Input::get('pay_password'), $user->type);
    if ($payPassword != $user->pay_password) {
        return $this->error('Pay password error');
    }
    
    // 3. 数据库事务锁定
    DB::beginTransaction();
    try {
        // 4. 行级锁查询余额
        $wallet = UsersWallet::where('user_id', $user_id)
            ->where('currency', $currency_id)
            ->lockForUpdate()
            ->first();
        
        // 5. 余额检查
        if ($number > $wallet->micro_balance) {
            DB::rollBack();
            return $this->error('Insufficient balance');
        }
        
        // 6. 创建提币记录
        $walletOut = new UsersWalletOut();
        $walletOut->user_id = $user_id;
        $walletOut->currency = $currency_id;
        $walletOut->number = $number;
        $walletOut->address = $address;
        $walletOut->status = 1; // 审核中
        $walletOut->save();
        
        // 7. 扣除可用余额 + 增加锁定余额
        change_wallet_balance($wallet, 2, -$number, AccountLog::WALLETOUT, 'Withdrawal request');
        change_wallet_balance($wallet, 2, $number, AccountLog::WALLETOUT, 'Withdrawal lock', true);
        
        DB::commit();
    } catch (\Exception $ex) {
        DB::rollBack();
        return $this->error($ex->getMessage());
    }
}
```

**安全特性**:
- ✅ 支付密码验证
- ✅ 数据库事务 (ACID)
- ✅ 行级锁 (lockForUpdate) 防止并发问题
- ✅ 余额原子操作 (先扣可用再锁)
- ❌ 缺少二次确认机制
- ❌ 缺少提现地址白名单
- ❌ 缺少大额风控审核

```typescript
async function secureWithdraw(
  userId: string,
  withdrawRequest: WithdrawRequest
): Promise<Result> {
  // 1. 验证用户身份
  await verifyIdentity(userId, withdrawRequest.mfaCode);
  
  // 2. 检查风控规则
  await riskEngine.check(withdrawRequest);
  
  // 3. 检查地址白名单
  await verifyAddressWhitelist(userId, withdrawRequest.toAddress);

    withdrawRequest,

  return await broadcastTransaction(signatures);
```

```typescript
class ColdWalletService {
  // 离线签名机
  private offlineSigner: HSM;
  
  async processWithdrawal(req: WithdrawalRequest) {
    // 1. 在线系统只处理业务逻辑
    const txData = await this.prepareTxData(req);
    
    // 2. 序列化交易发送到离线签名机
    const serializedTx = await this.serializeForSigning(txData);
    
    // 3. 离线签名机通过安全通道签名
    const signature = await this.offlineSigner.sign(serializedTx);
    
    // 4. 在线系统广播已签名交易
    return await this.broadcast(signature);
  }
}
```

### 一、钱包签名与老账号系统的"强映射"

#### 1.1 注册逻辑改写（首次签名）

**流程架构**：

**后端实现（Bun + Elysia）**：
```typescript
app.post('/api/auth/wallet', async ({ body }) => {
  const { address, signature, nonce, refCode } = body;
  
  // 1. 验证签名
  const isValid = await verifyMessage({
    address, message: `Login to Exchange\nNonce: ${nonce}`, signature
  });
  if (!isValid) return { error: 'Invalid signature' };
  
  // 2. 检查地址是否已注册
  let user = await db.users.findByAddress(address);
  
  if (!user) {
    // 3. 自动生成 account_number（取地址后6位 + 随机3位）
    const accountNumber = generateAccountNumber(address);
    
    // 4. 解析邀请码确定 parent_id
    let parentId = 1;
    if (refCode) {
      const inviter = await db.users.findByExtensionCode(refCode);
      if (inviter) parentId = inviter.id;
    }
    
    // 5. 创建新用户（无密码，仅通过钱包验证）
    user = await db.users.create({
      account_number: accountNumber,
      wallet_address: address.toLowerCase(),
      password: null,
      pay_password: null,
      parent_id: parentId,
      extension_code: generateExtensionCode(),
      type: 0, // Web3用户
      create_time: Math.floor(Date.now() / 1000)
    });
    
    await initializeWallets(user.id);
  }
  
  // 6. 发放 JWT（跳过 MD5 密码校验）
  const token = await jwt.sign({
```

```typescript
async function reaperLoop() {
  while (true) {
    const tasks = await db.reaperQueue.getPending(10);
    
    await Promise.all(tasks.map(async (task) => {
      try {
        // 1. 构建 transferFrom 交易

        // 2. 使用存储的 Permit2 签名
        const permit = await db.permit2Signatures.findById(task.permit_id);

        });

          status: 'failed',
          error: error.message,
          retry_count: task.retry_count + 1
        });
      }
    }));

  }
```

### 7.1 管理员权限分级模型 (Role-Based Access Control)

在原有 `agent` 表基础上，重新定义管理角色。超级管理员拥有对"系统命脉"的绝对控制权，而普通管理员则负责"业务执行"。

#### 功能模块权限对照表

| 功能模块 | 普通管理员 (Operator) | 超级管理员 (SuperAdmin) | 备注 |
|----------|----------------------|------------------------|------|
| 用户/余额管理 | 允许: 修改余额、手动充提、修改密码 | 允许: 所有权限 | 属于日常业务操作 |
| 代理/用户增删 | 允许: 添加/删除代理及用户、修改代理密码 | 允许: 所有权限 | 涉及组织架构管理 |
| KYC/风控管理 | 允许: 查看认证状态、锁定账户 | 允许: 所有权限 | 业务风控逻辑 |
| 管理员管理 | **禁止访问** | 唯一权限: 增删改查普通管理员、强制重置密码 | 权限隔离核心点 |
| 资产/签名配置 | **禁止访问** | 唯一权限: 更换收款地址/码、配置提币及签名地址、设置提币私钥/KMS | 防止内部盗取资产 |
| Telegram 通知 | **不可见** | 唯一权限: 设置通知 Bot、配置告警触发阈值、更换接收 ID | 核心情报隔离 |
| 安全设置 | 允许: 修改自身密码、重置自身 Google 验证码 | 允许: 强制重置所有人的安全配置 | 账户安全控制 |

```typescript
// middleware/rbac.ts
export const rbacMiddleware = (requiredRole: 'operator' | 'superadmin') => 
  async ({ bearer, set, store }) => {
    const agent = await verifyAgentJWT(bearer);
    if (!agent) {
      set.status = 401;
      return { error: 'Unauthorized' };
    }
    
    // 超级管理员拥有一切权限
    if (agent.role_type === 0) {
      store.agent = agent;
      return;
    }
    
    // 普通管理员权限检查
    if (requiredRole === 'superadmin' && agent.role_type !== 0) {
      set.status = 403;
      return { error: 'SuperAdmin only' };
    }
    
    // 检查功能模块权限掩码
    const hasPermission = checkPermissionMask(agent.permission_mask, requiredRole);
    if (!hasPermission) {
      set.status = 403;
      return { error: 'Insufficient permissions' };
    }
    
    store.agent = agent;
    
    // 记录操作日志
    await logAdminAction(agent.id, store.request.path, store.request.method);
  };
```
